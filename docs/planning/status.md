### What works today

- **Name**: the product is **DoodleWhirl!** (renamed from PictioTheme on 2026-10-05). The UI, page titles, favicon and docs use it; the repo, `@pictiotheme/*` packages and database keep the old name.
- **Home = lobby** (`/`, [user-flows.md](../product/user-flows.md#2-home-page-the-lobby-is-the-front-door), [screens.md](../design/screens.md#1-home-the-lobby-is-the-front-door)): every way into a game is one click and there's no name form. Under the logo: **⚡ Quick play** (`POST /api/rooms/quick-play`: the fullest waiting public room with space, else a public match with space, else a new public room), **🔒 New private room** (one click, default deck; settings in the waiting room), a **join field** that also takes a pasted invite link, and the live **public rooms as sticky notes** with an "N doodling now" count (`online` on `GET /api/rooms/public`). First-time visitors get a **silly name** ("Sneaky Pickle", `lib/silly-name.ts`) and their initial as avatar (`useEnsureIdentity`, features/identity), editable with the "Playing as…" chip. **Invite links skip the name form** too. Phones see a short note instead of the actions. It's the `client:only` island `components/home/HomeLobby.tsx` (W2 exception); entering a room is a full page load of `/r/CODE`. On screens bigger than 1080p the page grows with the viewport (`fluidRoot` on `BaseLayout`: the rem goes from 16px to 20px at 1440p and 28px at 4K, using the tighter of width and height). The app shell (`app.astro`, so rooms too) uses it as well since 2026-10-05; before, a 4K room kept 16px text on a huge board. The choosing cards size their padding and gap from the card itself (each slot is a CSS container), so the word stays on the card at any board size.
- **Logo** (on `/`): ruled paper on a desk, "DoodleWhirl!" in Cherry Bomb One (self-hosted through Astro's fonts API, only the Latin file preloaded) as sticker letters you can nudge, grab and fling (spring-tethered physics in `components/hero/letter-physics.ts`, hand-written, no library), a pencil whose tip sits in front of the "!", and a swirl under "Whirl!". One small `client:load` island; reduced motion gets the static picture.
- **Doodle desk** (on `/`, behind the paper): lanes of faded hand-drawn doodles drift left and right across the desk (`components/home/DoodleDesk.astro`, art in `doodles.ts`, seeded layout in `doodle-lanes.ts`). CSS only, no JS; still with reduced motion. Around the paper lie props you can play with (mug sloshes, eraser rubs into crumbs, brush splats, crayons scribble doodles; `DeskProps.tsx`, a small `client:load` island, from 1024 px wide) and a coffee ring on the paper's corner (`CoffeeRing.astro`). Possible next steps: doodles that draw themselves in, the most-liked room covers as one lane.
- **Home → room continuity** (2026-10-05): the room lies on the same desk as the home page (`app.astro`; the lanes run on the wall clock, so they carry on where they were, and they stop and fade during a match). Its sheet and the guess column are paper, and the header has the logo's coloured sticker letters (`ui/StickerLogo.tsx`). Going between the pages is a cross-document view transition (`global.css`): the logo shrinks into the header and the home page's paper straightens into the room's sheet. Coming back home skips the intro. To give them somewhere to land, `app.astro` server-renders the room's empty frame (`routes/room/RoomShell.tsx`) as the first frame, and the same frame shows while joining and on errors. Chrome, Edge and Safari 18.2+ animate it; others just navigate; reduced motion turns it off. Ideas not done yet: an exit animation on the home page while the room is being made, music carrying into the waiting room, a mug beside the room's sheet, and restyling the waiting room's panels in ink and stickers.
- **Waiting room** ([screens.md](../design/screens.md#3-the-waiting-room-choosing-the-deck-house-rules), redesigned 2026-10-05): the room's name is the page title in the logo's sticker letters (they pop on, and again after a rename; the host renames in place with ✏️, `RoomTitle`), then one "ready" card (deck and rules at a glance with the longest the match can take, the code to share, Start game), then the host's workspace: the **deck library** (`DeckChooser` in features/deck-picker) beside the **house rules**. The library keeps a fixed height and scrolls inside with sticky headings, has category chips from the most shared tags (`top-tags.ts`, searched on the server like the search box), ✨ Generate in its header, and pages "Show all" 48 at a time. The rules are grouped (Pace with Quick/Classic/Long presets, steppers and a match-length estimate from `match-length.ts`; Cards; Guessing; Room). The layout follows the room's own width (CSS size container). For the host, Draw yourself starts as a one-line prompt. Picking a deck sends `room:settings`, so the room switches for everyone. There's no create-room form; `/play` redirects to `/` (Caddy in production, `src/middleware.ts` in dev).
- **❤️ Likes and room covers** ([game-rules.md](../product/game-rules.md#likes-and-the-room-cover)): guessers like the drawing (board corner, drawing and reveal); when a reveal ends with strictly more likes than the room's cover, the drawer's browser gets `cover:request`, paints the strokes off screen, cuts them out (`cutoutFitted`, features/avatar) and uploads a 320×240 PNG; the server keeps it in memory with the room and the home page's room note shows it, boiling like the players (`features/likes`, game-core `likes.ts`). The room list now only shows rooms with someone connected.
- **Room name and public/private** (host, any time: the name in the waiting room's title, public under House rules, both also on results): `room:details` client and server messages; the home page's room notes pick it up on their next refresh.
- **"Draw yourself!"** (waiting room, features/identity `DrawYourself`): players still on their generated initial draw an avatar and pick a name while friends arrive; `PUT /api/rooms/:code/me` updates everyone's player list through a game-core `identity` event, with no reconnect (`connectRoom` reads the current identity at each connect). The same works any time, mid-match too, from the "you" sticker in the room header (`RoomIdentityChip`: avatar, your name in your player-list handwriting, ✏️); once you've drawn, the waiting room shows no second link for it.
- **Room** (`/r/ABC-DEF`): invite links ask for a name first. The waiting room has the code, copy-invite button, and host-editable settings. Matches have choosing/drawing/reveal phases, hints, timer, scoring, early end when everyone has guessed, and results with awards and play again.
- **Drawing**: brush, eraser, fill (grown 1 px into stroke edges so no unfilled ring is left), sizes, opacity, 24-colour palette plus a custom colour, undo/redo/clear, keyboard shortcuts. Live sync to every guesser, including late joiners and reconnects.
- **Brush controls**: right-drag or Ctrl/⌘-drag on the canvas changes size (↔) and opacity (↕), or tolerance on Fill. A ring previews the real on-screen brush size and flashes filled with the real ink and a "24 px · 60%" label on every change. Shortcuts are layout-independent (`[` `]` `-` `=`, Shift for ×2, digits for opacity). See [drawing-tools.md](../product/drawing-tools.md#adjusting-size-and-opacity).
- **Colours**: eyedropper (hold `Alt` to preview the colour under the pointer, `Alt`+click or a quick right-click to pick it up), `X` swaps to the previous colour, `C` opens the swatches, recent colours and full picker at the pointer. See [drawing-tools.md](../product/drawing-tools.md#picking-and-sampling-colours).
- **Guessing**: correct / close (red, redacted for others) / wrong, guess visibility on/off, a solvers-only chat channel, guess bubbles above each player's character.
- **Sounds** ([sounds.md](../design/sounds.md)): shuffle, deal and flip in time with the card animation, your turn, correct/close/someone-solved, hints, a quiet clock tick for the last 10 seconds, a very faint pencil scribble that follows the line's speed (the drawer and guessers both hear it), a glug for the paint bucket, turn over, results jingle, chat and join/leave pops. All CC0 (Kenney, Freesound). The 🔊 button (room and lobby headers, and the home page's corner) has mute all, main volume and six groups (Cards & turns, Guesses, Drawing, Clock ticking, Chat & players, Music). The home page loops "Flowerbed Fields" by Zane Little after the first click (license still to confirm), saved in localStorage. Rooms use `onRoomMessage` from `realtime/` to hear applied messages, and `watchDrawing` follows the stroke model.
- **Players as their doodles** ([screens.md](../design/screens.md) §4): no sidebar. The players stand in the left margin of the same sheet of paper as the canvas. Each one is their avatar cut out of its background (`features/avatar/cutout.ts`; avatars saved before this are re-cut once in the browser by `AvatarUpgrade`), with SVG line boil and a gentle sway, the name in one of ten messy handwriting fonts, thickened with a thin text stroke so it reads (`name-font.ts`, self-hosted through Astro's fonts API and loaded in `app.astro`), and the points on a scribbled sticker that counts up with a floating "+N" at the end of a turn. The sheet always renders light: `dark:` utilities don't apply inside `[data-paper]` (the custom `dark` variant in `global.css`).
- **Leaderboard**: during a match the characters are sorted by score with ranks, and slide (overtakers grow, wiggle and glow) when the order changes (`features/player-list/leaderboard.ts`, `use-leaderboard-motion.ts`). Turn order is unaffected.
- **Host controls**: pause/resume, skip, end match, kick, make host, and **🚪 Close room** (room header, any phase, after a confirm: `room:close` ends a running match so it's recorded, then every socket closes with 4007 and the room is gone). Others can vote-kick.
- **Resilience**: reconnect with backoff (fresh join token each time), the drawer's 15s grace period, host handover, auto-pause when one player is left, graceful server shutdown.
- **AI deck generation** (on for everyone; `DECK_GENERATION=off` is the kill switch): "✨ Generate a deck" in the host's deck picker (waiting room) takes a theme, notes, difficulties and silly on/off, shows progress while the server makes the deck (~1 min), then saves it to the `decks`/`cards` tables and makes it the room's deck. Generated decks are listed as "yours" in the deck picker. One running job per player; a restart fails running jobs. **Limits** (rolling 24 h, failed jobs don't count): 1 deck per player, 3 per IP (stored only as an HMAC of the IP), and a global $5 budget, then "busy, try later". All set in config (`GENERATION_*`); `GENERATION_LIMITS=off` turns them off for development. The panel shows "You can make one deck a day" or when the next one is available. Themes, notes, cards, alternates, titles and tags go through the blocklist (`generation/content-check.ts`). Under the hood, `modules/generation` turns a theme, the chosen difficulties and a silly on/off flag into a validated deck via OpenRouter: prompt → model (structured output) → deterministic cleanup → one top-up call if a pool is short. Try it with `pnpm --filter @pictiotheme/server deck:generate --theme "pirates" --difficulties easy,medium --silly` (needs `OPENROUTER_API_KEY` in `apps/server/.env`). It uses `openai/gpt-6-luna` (fallback `gpt-6-luna-pro`) with the examples prompt, picked by a blind-graded eval of 11 models and 3 prompts ($0.52): see [model-eval-2026-10.md](../technical/model-eval-2026-10.md) and decisions.md D6. A deck costs ~$0.004 and takes ~1 minute. The free `stealth/space-bunny-alpha` still works for experiments (commented out in `.env`).
- **Deck back covers** ([decks.md](../product/decks.md#back-cover)): while a deck generates, the creator draws its 3:4 back cover on a pad (or skips). The deck is handed back once it's published and the cover is saved or skipped; if generation fails, the drawing is kept and re-sent with the retry. Covers are stored content-addressed in `deck_covers` (`PUT /api/decks/generations/:id/cover`, `GET /api/decks/covers/:id`) and shown in the deck picker, beside the room code in the waiting room, on results, and as the card backs while choosing (the room's `deck` carries `coverId`). Creators can redraw a cover later with ✏️ on their decks in the deck picker (`PUT /api/decks/:id/cover`, owner = whoever's generation job made the deck). The cover pad has the game's full drawing toolbar, with touch-sized targets on tablets; where there's room the tools and Save/Skip sit in a column beside the pad (stacked on narrow screens), and while generating the deck library drops its fixed height and grows to fit, so the pad never scrolls inside a box (2026-10-05). Skipping a cover you've drawn on asks first. Decks without one (curated decks, skipped ones) show a default cover made from the title (`features/deck-cover`).
- **Deck reports**: 🚩 on a saved deck in the waiting room and on results reports its cover or its cards/title (`POST /api/decks/:id/reports`, `deck_reports` table). 3 reports from different players hide the cover (the default cover shows) or the deck (it can't be picked or loaded). No moderator page yet to review or restore them.
- **Content**: 20 **curated decks** as JSON in `apps/server/src/modules/decks/curated/` (the 2 former built-ins plus 18 generated on 2026-10-04 for $0.07, not yet edited by hand; they keep the default title tile as their cover), seeded into `decks`/`cards` by `db:migrate` (upsert by slug: same id and cover on re-seed). 5 are featured (Halloween-season first). Plus players' generated decks. Every deck lives in the database now.
- **Deck picker** (create room): a grid of covers in sections (your decks, featured, more decks; 4 each until "Show all"), and a search box over titles and tags of all public decks, typo-tolerant (`GET /api/decks?q=`, `pg_trgm`).
- **Profanity filter** (`game-core/src/moderation/profanity.ts`, on the `obscenity` list with leetspeak handling and a list of allowed phrases like "Moby Dick" or "Cockpit"): chat and guesses are masked for other players, and offensive player or room names are refused at create/join.
- **Metrics** ([data-model.md](../technical/data-model.md#metrics)): product events in our own `product_events` table (rooms created, matches started/ended with the reason, turn results, time from landing to the first turn, phone gate, device per player), card stats on `cards` (offered, picked by the drawer, drawn, guessed) and the drawer's 👍/👎 on the face-up options (`card_votes`, via `turn:vote`). `pnpm --filter @pictiotheme/server metrics:report [--days N]` prints the launch metrics against their targets and the weakest cards. Best-effort: a failed write never affects a game.
- **Tablets** ([drawing-tools.md](../product/drawing-tools.md#touch-and-stylus), [screens.md](../design/screens.md) §4): below 1024 px wide (tablets in portrait) the room stacks the board over Guesses/Players tabs with the guess input pinned, and nothing but the panels scrolls (when the header wraps tall, the board area gives up the space and scrolls, never the page). The toolbar has touch-sized targets and a 💧 eyedropper button. Pen pressure is recorded, only one pointer draws at a time, and touches stop drawing once a pen has been seen (palm rejection, `canvas/engine/pointer-gate.ts`). No double-tap zoom or long-press callout. The lobby stacks below 1024 px. Tested with Chrome's iPad emulation (`e2e/tablet.spec.ts`); not yet on a real iPad or Android tablet.
- **Phone gate**: phones (touch screen whose shorter side is under 600 px) get "DoodleWhirl! needs a bigger screen" with the link to copy, and a "Try anyway". Tablets and desktops go straight in (`features/phone-gate`).

## How to run and verify

```sh
pnpm install
pnpm db:up                                            # Postgres 18 on :5433
cp apps/server/.env.example apps/server/.env          # once
pnpm --filter @pictiotheme/server db:migrate          # also seeds the curated decks; re-run after pulling
pnpm dev                                              # server :3000, web :4321 → http://localhost:4321
```

Before calling any change done:

```sh
pnpm check                                  # typecheck, lint, import boundaries, all unit tests
pnpm format:check
pnpm --filter @pictiotheme/web test:e2e     # two real Chrome browsers play a turn (UI changes)
```

Current counts: 397 unit tests (protocol 5, game-core 128, server 167, web 97) and 11 browser spec files (close-room, landing with 7, likes, avatars with 3, phone-gate with 3, play-a-turn, brush-controls, color-shortcuts, generate-deck with 5 tests (one room each: run that file alone with rate limits on), deck-picker, tablet with 2: iPad emulation in Chrome, pens and touches through the DevTools protocol). The browser specs need the curated decks in the dev database (`db:migrate`). All pass when run one at a time (`--workers=1`). Against a reused dev server the HTTP rate limits (room creation 5/min, quick play 10/min, joins 10/min) still apply unless it runs with `RATE_LIMITS=off`, so running specs in parallel, or re-running them back to back, can trip it: wait a minute between runs. Specs open players with `newPlayerPage` (`e2e/support.ts`), which hides the Astro dev toolbar so it can't intercept clicks. Specs run two at a time and share one server, so the home page lists other specs' public rooms and the centred logo can shift: landing specs measure letters against their own wrapper, not the page.

## Implementation decisions not covered elsewhere

- Avatars are drawn by players (`features/avatar/AvatarPad`, which reuses the canvas stroke model and renderer). Create/join send a 128×128 PNG data URL; the `avatars` server module validates it, stores it content-addressed in Postgres, and the join token, `PublicPlayer.avatar` and `<img src=/api/avatars/:id>` use only the id. The player list shows the avatar large and the name small.
- Hidden decks and covers only affect rooms that load the deck afterwards: a room already playing it keeps its cards and cover. The same goes for a redrawn cover.
- HTTP rate limits are on everywhere except automated tests (`RATE_LIMITS=off` in the test config). The same goes for the generation limits (`GENERATION_LIMITS=off`); their tests turn them on with random client IPs, since the test database keeps jobs between runs.
- Curated decks are never hidden by reports automatically (griefing); their reports wait for the moderator page. Re-seeding replaces their cards (card ids change), which card stats will need to handle.
- One hosted room per player: creating a new room closes your previous one if nobody else is in it.
- The client clears the canvas on a new turn by itself, because the server doesn't send `draw:clear` between turns ([frontend-guidelines.md](../technical/frontend-guidelines.md#how-a-room-screen-works)).
