### What works today

- **Name**: the product is **DoodleWhirl!** (renamed from PictioTheme on 2026-10-05). The UI, page titles, favicon and docs use it; the repo, `@pictiotheme/*` packages and database keep the old name. The favicon is the brand in miniature: a sticker of ruled paper with a purple whirl and the logo's yellow pencil. No slogan anywhere; the home page title is just "DoodleWhirl!".
- **One profile for every game** (2026-10-21, [decisions.md](../technical/decisions.md#d13--one-profile-for-every-game-a-portal-a-shared-guest-and-an-account-widget) D13): your name and drawing are a profile on the server (`players` table, `GET`/`PUT /api/me`, the `players` module), shared by DoodleWhirl, Doodle Tower and the new **games portal** (`apps/portal`: the games list and "You, as a guest", with the shared editor and drawing pad). The guest cookie is set for the parent domain (`COOKIE_DOMAIN`; renamed `pt_guest` → `play_guest`, and the old one still works and is moved over), so every subdomain is the same guest. Every game shows the **account widget** (`packages/account`) in its top-left corner: "Name yourself", your name with a Guest tag, or just your avatar during a match, with "All games" in its menu. DoodleWhirl's widget is its "you" sticker (now "Playing as guest", and avatar-only in the room header during a match); Doodle Tower uses the shared widget in its colours. A silly name is saved as not chosen (the widget keeps asking for a real one) and never replaces a chosen name. Each game moves the identity it kept in browser storage into the profile once. A rename in one game shows in another's open tab when you switch back to it. Tested: server e2e (`players.e2e.test.ts`, the tower rename in `tower.e2e.test.ts`), tower-core's `identity` event, the profile rules (`packages/account`), and a browser run across the three sites (name and draw on the portal → DoodleWhirl and Tower show it; Tower rename → the portal; a silly name in Tower; the old DoodleWhirl identity imported; avatar-only in a DoodleWhirl match; a rename in a Tower waiting room reaches the crew list). Structure follow-ups (same day): the request's actor carries the player's row id (`playerKey`), so stored records use `g_<players.id>` however the player signed in, ready for accounts; `@pictiotheme/account` is the store and rules only, the widget, editor and pad are `@pictiotheme/account/ui` (DoodleWhirl ships none of them; enforced by `account-core-has-no-ui`); the name rule is protocol's `nameAfter`, used by the server and the store; profanity moved out of `game-core` into `packages/moderation`. Then: each game's identity store is `createGameIdentity` (the profile mirror and fallback-avatar cache, once); in a room, your name and avatar **follow the profile** (`useRoomFollowsIdentity` on each room page sends any change, from this game, another game or the portal, to the game's `PUT …/rooms/:code/me`), replacing the editors' save callbacks; `packages/sites` holds where every site lives (portal and game links, the server's dev origins); the Caddyfile shares `invite_previews` and `static_files` snippets (its compiled config is unchanged); CI builds every app with one filter; [adding-a-game.md](../technical/adding-a-game.md) walks through how the games fit together and every step to add one, and backend rule B30 puts each new game's routes under `/api/<game>/`. Not deployed yet (see Next tasks).

- **Scoring, hints and rush** (2026-10-10, [game-rules.md](../product/game-rules.md#scoring)): guessers get 100–300 for speed, plus +100/+50/+25 for the first three. The drawer gets 50 per guesser (counting 2–8), at full points once half the room gets it, with a steeper multiplier (easy 1, hard 2, Chaos 2; medium went on 2026-10-11) so hard cards pay. Only guessers still connected count (before, players waiting out a disconnect lowered the drawer's share). Hints scale with the card: one per 5 letters, at most a third of any word, spread from ½ to ⅘ of the time, a letter per word first, first letters last. **Rush** (host toggle, off by default, also live mid-match): the first correct guess cuts the clock to a quarter of the draw time (15–30 s) and points drain to 100; the header shows a draining bar with the current points (`RushMeter`), and players with no hint yet get one. A ❤️ **Crowd favourite** award goes to the match's most-liked drawing. The drawer's choice cards now show the drawer's multiplier. Rules in game-core (`scoring.ts`, `word-mask.ts`, `match.ts`), unit-tested; the rush meter has an e2e (`e2e/rush.spec.ts`, 3 players in Chrome). The constants need checking in a real playtest; the card multipliers could later be tuned from the `turnEnded` metrics (solve rate per difficulty).
- **Guessing**: correct / close (red, redacted for others) / wrong, guess visibility on/off, a solvers-only chat channel, guess bubbles above each player's character.
- **Feed system messages** (2026-10-08, `GuessFeed.tsx`): the game's lines never look like chat. Players' lines are left-aligned with their name; the game's are centred with no name. Each turn opens with a dashed divider ("Round 2/3 · Ana draws", the drawer's name in their player-list hand), the reveal is an ink-outlined sticker card ("The word was **Witch**, drawn by Ana"), "Bo guessed it! First!" is a green pill, notices and pause/resume are grey pills, errors red ones, and the match ends with a "🏁 Match over" divider. Solvers' chat carries a "Solvers" tag as well as its green tint (W14). The reducer adds the `turn`, `pause` and `matchOver` feed items client-side (no protocol change); `phase:choosing` and `room:paused` re-sent on resume don't repeat them.
- **Feed scrolling** (2026-10-19, `GuessFeed.tsx`, `e2e/chat-scroll.spec.ts`): the feed sticks to the latest line while you are at the bottom. It follows the last item's id, not the feed's length, because the feed is capped at 200 items, so its length stops changing (that cap was why long chats stopped following). Scrolling up unsticks it and shows a **Jump to latest ↓** sticker (with a red dot when new lines came in). Your own lines always bring it back to the bottom.
- **Guess bar and voice guessing** (2026-10-08, decision D11): you type on a strip of paper of its own, a little below the feed (`features/guess-feed/components/GuessBar.tsx`; `GUESS_STRIP` in `ui/room-frame.ts`, which the empty `RoomShell` lays down too). A sticker tab says what it's for (Your guess / Solvers' chat / Chat / You're drawing!), typed text is in Gochi Hand when the room's language is Latin-script, and Send is a small ↵ keycap (Enter does the same). Beside it, a doodled 🎤 says it instead: **hold** it while you talk (≥300 ms is a hold) and letting go sends at once, or **tap** to leave it open and say guess after guess until you tap again. To be quick, a spoken guess doesn't wait for the recogniser's end of speech (about a second of silence plus a network round trip): words that stop changing for 400 ms (`SETTLE_MS` in `use-voice.ts`) go out, and if the recogniser's final words differ (ignoring case and punctuation, `sameWords`) they go out too. A speech bubble over the strip shows what it hears, then "✓ “…” sent", or why it couldn't ("The microphone is blocked…"). Spoken chat lands in the field to check first. Esc cancels. It uses the browser's Web Speech API (`speech.ts`, `use-voice.ts`): free, nothing to download, only the recogniser's top result, in the room's language with its flag's country (`en-GB`, `es-MX`, `zh-TW`). Chrome, Edge and Safari; Firefox gets no mic. Chrome sends the audio to Google to transcribe it: say so in the privacy page once there is one. Not yet tried with a real microphone in Safari or on a tablet; `SETTLE_MS` may need tuning once it is.
- **Sounds** ([sounds.md](../design/sounds.md)): shuffle, deal and flip in time with the card animation, your turn, correct/close/someone-solved, hints, a quiet clock tick for the last 10 seconds, a very faint pencil scribble that follows the line's speed (the drawer and guessers both hear it), a glug for the paint bucket, turn over, the results' podium ceremony (scribble, thumps, drumroll, cymbal, fanfare, pops, a boing for pokes; the old results jingle now only plays with reduced motion), chat and join/leave pops, and a paper crumple and kick when the host closes the room (synthesised for the game). The 🔊 button (room and lobby headers, and the home page's corner) has mute all, main volume and six groups (Cards & turns, Guesses, Drawing, Clock ticking, Chat & players, Music). The home page loops "Flowerbed Fields" by Zane Little after the first click (license still to confirm), saved in localStorage. Rooms use `onRoomMessage` from `realtime/` to hear applied messages, and `watchDrawing` follows the stroke model.
- **Players as their doodles** ([screens.md](../design/screens.md) §4): no sidebar. The players stand in the left margin of the same sheet of paper as the canvas. Each one is their avatar cut out of its background (`features/avatar/cutout.ts`; avatars saved before this are re-cut once in the browser by `AvatarUpgrade`), with SVG line boil and a gentle sway, the name in one of ten messy handwriting fonts, thickened with a thin text stroke so it reads (`name-font.ts`, self-hosted through Astro's fonts API and loaded in `app.astro`), and the points on a scribbled sticker that counts up with a floating "+N" at the end of a turn. The sheet always renders light: `dark:` utilities don't apply inside `[data-paper]` (the custom `dark` variant in `global.css`).
- **Leaderboard**: during a match the characters are sorted by score with ranks, and slide (overtakers grow, wiggle and glow) when the order changes (`features/player-list/leaderboard.ts`, `use-leaderboard-motion.ts`). Turn order is unaffected.
- **Host controls**: pause/resume, skip, end match, kick, make host, and **Close room** (room header, any phase: `room:close` ends a running match so it's recorded, then every socket closes with 4007 and the room is gone). - **AI deck generation** (on for everyone; `DECK_GENERATION=off` is the kill switch): "✨ Generate a deck" in the host's deck picker (waiting room) takes a theme, notes and "🌀 Chaos cards too" (on by default), shows progress while the server makes the deck (~1.5–2.5 min), then saves it to the `decks`/`cards` tables and makes it the room's deck. Generated decks are listed as "yours" in the deck picker. One running job per player; a restart fails running jobs. **Limits** (rolling 24 h, failed jobs don't count): 1 deck per player, 3 per IP (stored only as an HMAC of the IP), and a global $5 budget, then "busy, try later". All set in config (`GENERATION_*`); `GENERATION_LIMITS=off` turns them off for development. The panel shows "You can make one deck a day" or when the next one is available. Themes, notes, cards, alternates, titles and tags go through the blocklist (`generation/content-check.ts`). Under the hood, `modules/generation` turns a theme and a Chaos on/off flag into a validated deck via OpenRouter: the easy and hard cards (prompt → model, structured output → deterministic cleanup → one top-up call if a difficulty is short), then the Chaos cards with their own prompt, cleanup and top-up. Try it with `pnpm --filter @pictiotheme/server deck:generate --theme "pirates" --chaos` (needs `OPENROUTER_API_KEY` in `apps/server/.env`). It uses `openai/gpt-6-luna` (fallback `gpt-6-luna-pro`), picked by a blind-graded eval of 11 models and 3 prompts ($0.52): see [model-eval-2026-10.md](../technical/model-eval-2026-10.md) and decisions.md D6. A deck costs ~$0.005–0.013. The free `stealth/space-bunny-alpha` still works for experiments (commented out in `.env`).
- **Chaos mode and better cards** (2026-10-11, decision D12, [game-rules.md](../product/game-rules.md#card-pool), [ai-deck-pipeline.md](../technical/ai-deck-pipeline.md#prompts)): a card is `easy`, `hard` or `chaos` (`Card.kind`); medium and silly cards are gone (migration 0011 deleted the silly cards and turned medium into easy). The house rules have a **Mode**: Normal (easy and/or hard) or 🌀 **Chaos** (only the deck's Chaos cards, no difficulties, no ratio). Chaos cards come from a second model call whose prompt ties every twist to what its subject is (the swap test; "Snowman in a sauna", not "Laminator painting a fence"), and cleanup allows each twist once per deck, 3 cards per subject and 3 stock activities. Easy cards "name it", hard cards "show it" (a scene from what the subject is known for), and a hard card that's a label on an easy card ("Cassiopeia snake queen") is dropped. Not every deck has Chaos cards: in Chaos mode a deck without them shows "Needs Chaos cards", Start waits, and the host's deck library offers "🌀 Make Chaos cards" (`POST /api/decks/:id/chaos`, any host, shared by every room on the deck, 5 per player and 15 per IP a day); rooms playing the deck reload it when they're saved. Hard and Chaos cards are matched by concepts in any order. `deck:quality` prints the automatic quality numbers for a set of decks (free): on the eval themes, stock activities went from 33.6% of the old silly cards to ~2% of Chaos cards and no twist repeats within a deck. Eval run: `evals/results/chaos-v2`. The curated decks were later replaced by 14 hand-written ones with Chaos cards (see Content). Not checked yet: the new prompts in other languages (the label and variety checks are English-only).
- **Deck languages** (2026-10-07, [decks.md](../product/decks.md#languages), decision D10): the host sets the room's language on the room card (the flag beside the deck's title, "Deck: … in 🇩🇪 Deutsch"; type to search 27 languages, `DECK_LANGUAGES` in protocol, flags from `country-flag-icons` because Windows has no flag emoji, given a hand-drawn look by a per-flag SVG filter in `ui/LanguageFlag`). It's `settings.language`; a match only starts with a deck in it (`DECK_LANGUAGE_MISMATCH`). Decks not in the room's language are marked "needs translating"; picking one, or keeping the room's deck after a language change, opens the translate panel (`features/generate-deck` `TranslateDeckPanel`: just the cover, title, flag ➜ flag and a Translate button; the room card shows a small "Needs translation" chip beside the language), and `POST /api/decks/:id/translations` returns the saved translation or a job to poll (shared between hosts). Translations are `decks` rows with `source_deck_id` (migration 0009), made from the original by `translateDeck` (names kept or localised, cards that don't work dropped, <60% kept fails), 5 per player and 15 per IP a day. Lists (`?language=`) show each deck in the room's language when translated. Generation writes in the room's language (a rule in the prompt, plus a script check in cleanup), and a **theme check** call refuses themes in another language (`THEME_WRONG_LANGUAGE`) or too unclear (`THEME_UNCLEAR`) before a job starts. The check has its own model (`THEME_CHECK_MODEL`, default the deck model: an eval of 11 models found luna the most accurate and already ~$0.0001 a check; `openai/gpt-oss-20b` is the cheaper switch), every check is recorded in `theme_checks` and counted in the daily budget, and refused checks are capped (20 per player, 60 per IP a day). The host's language is remembered in the browser for their next room; Quick play only matches public rooms in it. The guess input ignores Enter while an IME composes. Not checked yet against the real model: translation quality (Pokémon names etc.) needs a manual pass with `OPENROUTER_API_KEY`, and the eval script doesn't cover them.
- **Deck back covers** ([decks.md](../product/decks.md#back-cover)): while a deck generates, the creator draws its 3:4 back cover on a pad (or skips). ## How to run and verify

```sh
pnpm install
pnpm db:up                                            # Postgres 18 on :5433
cp apps/server/.env.example apps/server/.env          # once
pnpm --filter @pictiotheme/server db:migrate          # also seeds the curated decks; re-run after pulling
pnpm dev                                              # server :3000, web :4321 → http://localhost:4321
pnpm dev:tower                                        # Doodle Tower :4322
pnpm dev:portal                                       # the games portal :4323 (cookies ignore ports, so all three share a guest)
```

Before calling any change done:

```sh
pnpm check                                  # typecheck, lint, import boundaries, all unit tests
pnpm format:check
pnpm --filter @pictiotheme/web test:e2e     # two real Chrome browsers play a turn (UI changes)
```

Current counts: 558 unit tests (protocol 7, game-core 173, server 218, web 160) and 17 browser spec files (emotes, rush, results-setup, chaos-mode, voice-guess (a stand-in recogniser), room-language with 2, close-room, landing with 7, likes, avatars with 4, phone-gate with 3, play-a-turn, brush-controls, color-shortcuts, generate-deck with 5 tests (one room each: run that file alone with rate limits on), deck-picker, tablet with 2: iPad emulation in Chrome, pens and touches through the DevTools protocol). The browser specs need the curated decks in the dev database (`db:migrate`). All pass when run one at a time (`--workers=1`). Against a reused dev server the HTTP rate limits (room creation 5/min, quick play 10/min, joins 10/min) still apply unless it runs with `RATE_LIMITS=off`, so running specs in parallel, or re-running them back to back, can trip it: wait a minute between runs. Specs open players with `newPlayerPage` (`e2e/support.ts`), which hides the Astro dev toolbar so it can't intercept clicks. Specs import `test` from `e2e/support.ts`, which closes the contexts a test opened when it ends: left open, every earlier test's players stayed in their rooms for the rest of the worker, and on CI the load made a quick touch read as a long-press (2026-10-13). The player who picks a card opens with `DRAWER` (reduced motion): the server picks after 10s, and on CI the card table's deal animation used most of that. Specs run two at a time and share one server, so the home page lists other specs' public rooms and the centred logo can shift: landing specs measure letters against their own wrapper, not the page. Firefox and WebKit get 120s per test instead of 60s: on CI, setting up a turn in WebKit alone has taken 57s, mostly loading dev modules into each fresh context.

## Implementation decisions not covered elsewhere

- Avatars are drawn by players (`features/avatar/AvatarPad`, which reuses the canvas stroke model and renderer). Create/join send a 128×128 PNG data URL; the `avatars` server module validates it, stores it content-addressed in Postgres, and the join token, `PublicPlayer.avatar` and `<img src=/api/avatars/:id>` use only the id. The player list shows the avatar large and the name small.
- Hidden decks and covers only affect rooms that load the deck afterwards: a room already playing it keeps its cards and cover. The same goes for a redrawn cover.
- HTTP rate limits are on everywhere except automated tests (`RATE_LIMITS=off` in the test config). The same goes for the generation limits (`GENERATION_LIMITS=off`); their tests turn them on with random client IPs, since the test database keeps jobs between runs.
- Curated decks are never hidden by reports automatically (griefing); their reports wait for the moderator page. Re-seeding replaces their cards (card ids change), which card stats will need to handle.
- One hosted room per player: creating a new room closes your previous one if nobody else is in it.
- The client clears the canvas on a new turn by itself, because the server doesn't send `draw:clear` between turns ([frontend-guidelines.md](../technical/frontend-guidelines.md#how-a-room-screen-works)).
